1. 최종 목표
-----------

mayb-log을 다음 구조로 개편한다.

- Cloudflare Workers를 production HTTP runtime으로 사용
- Express를 HTTP/routing/middleware layer로 사용
- EJS를 server-rendered HTML template engine으로 사용
- D1을 관계형 데이터 저장소로 사용
- R2를 게시글 이미지 저장소로 사용
- Workers Static Assets로 CSS/브라우저 JS/vendor 파일 서빙
- semantic HTML + plain CSS + vanilla JS
- htmx는 필요할 때만 progressive enhancement로 사용
- Marked로 저장 시 Markdown -> HTML
- Prism으로 fenced code highlighting
- browser-image-compression으로 브라우저 이미지 압축
- Turnstile + username/password + D1 opaque session
- JWT 없음
- Cloudflare Access 없음

핵심 철학:
- Express route를 보면 요청 흐름을 이해할 수 있어야 한다.
- db/*.js를 보면 실제 SQL 전체를 이해할 수 있어야 한다.
- views/*.ejs를 보면 페이지 HTML 구조를 이해할 수 있어야 한다.
- HTML을 거대한 JavaScript template literal로 만들지 않는다.
- SQL에서 해결할 filtering/sorting/pagination을 Worker JS로 옮기지 않는다.
- public request에서는 불필요한 D1 session read를 하지 않는다.
- dependency를 무조건 줄이는 것이 목적이 아니다. 유지보수를 쉽게 해주는 검증된 dependency는 사용한다.
- 대신 과도한 Repository/DAO/UseCase/Domain 계층이나 자체 framework는 만들지 않는다.

8. Session / CSRF
----------------

기존 안전한 session 구조는 유지한다.

- 256-bit opaque random session token
- raw token은 browser cookie
- D1에는 SHA-256(token)만 저장
- session은 7일
- active user인지 매 protected request에서 확인

Session cookie:
- HttpOnly
- Secure
- SameSite=Strict
- Path=/

추가 CSRF cookie:
- csrf=<session의 csrf token>
- Secure
- SameSite=Strict
- Path=/
- HttpOnly는 붙이지 않는다

이 CSRF cookie는 public Post detail에서 D1 session을 읽지 않으면서
X 삭제 POST에 CSRF token을 넣기 위해 사용한다.

Login 성공 시 session cookie와 csrf cookie를 같이 발급.
Logout 시 둘 다 제거.

모든 write POST:
1. session lookup
2. active status
3. CSRF compare
4. exact Origin
5. 실제 mutation

21. FTS5
-------

FTS5 사용.

FTS는 자유 텍스트 q에만 사용.

FTS에 넣지 않음:
- Tags
- Categories
- Series
- Author
- Date

이들은 SQL exact relation/filter/range로 처리.

FTS 대상:
- title
- subtitle
- description
- body plain text

posts에 body_text/search_text를 중복 저장하지 않는다.

Save 시:
body_markdown
-> Marked
-> body_html을 posts에 저장

동시에:
plain body text를 메모리에서 생성
-> FTS index에만 넣음

post_fts는 derived index.
rowid = posts.id.

가능하면 contentless FTS5 + trigram tokenizer를 사용.
현재 D1/SQLite에서 필요한 contentless delete/update option이 실제 지원되는지 migration/integration test로 확인.

trigger로 동작을 숨기기보다 db/posts.js 또는 db/search.js에서
insert/update/delete 시 FTS sync를 명시적으로 수행한다.

22. 1~2글자 검색
---------------

trigram FTS는 3 Unicode character 미만 substring을 최적화하지 못한다.

따라서:

q 길이 >= 3
-> FTS5 MATCH

q 길이 <= 2
-> SQL LIKE fallback

fallback 대상:
- title
- subtitle
- description
- body_markdown

LIKE의 %, _는 literal escape.

Tag/Category/Series는 FTS와 무관하다.

FTS 입력은 사용자 FTS query language로 실행하지 말고
literal phrase escaping을 적용한다.

23. Search SQL
-------------

금지:

const all = await getAllPosts();
all.filter(...);

모든 search result read 후 slice();

SELECT *;

SQL이 직접:
filter
join
sort
LIMIT/OFFSET
를 수행.

Category AND 예:

AND p.id IN (
  SELECT pc.post_id
  FROM post_categories AS pc
  WHERE pc.category_id IN (?, ?, ...)
  GROUP BY pc.post_id
  HAVING COUNT(DISTINCT pc.category_id) = ?
)

Series:
p.series_id IN (?, ...)

Tags:
각 tag마다 EXISTS (
  SELECT 1
  FROM json_each(p.tags)
  WHERE value = ?
)

Date:

R2 list가 source of truth.
